# 自定义通知

入口：Joker 设置 → 功能 → 通知 → 自定义通知。

替换微信的新消息通知样式：走自定义通知通道、同一会话的通知堆叠成一条，并在通知里直接回复或标记已读。与「通知进化」是两种实现方式，**两者互斥**。

## 设置

| 项 | 说明 |
| --- | --- |
| 静音时段 | 关闭 / 23:00-07:00 / 22:00-08:00 / 00:00-06:00，跨零点区间按跨天处理 |
| 仅提醒 @所有人 | 只有被 @ 时才提醒，其余消息一律静默 |
| 忽略微信免打扰 | 打开后即使会话被设为免打扰也照常提醒 |
| 免打扰会话直接静默 | 默认关闭：微信自身已会静默免打扰会话并保留「@我」提醒；打开后本功能会把这类通知一并丢掉 |
| 提示音 | 跟随微信 / 静音 / 系统默认 |
| 振动 | 跟随微信 / 关闭 / 系统默认 |
| 通知内快捷回复 | 在通知上直接回消息，不用切回微信 |
| 通知内一键标记已读 | 在通知上直接把这个会话标为已读 |

## 与「通知进化」的关系

两个功能都要接管微信的新消息通知，挂在同一个宿主方法上，所以**同时开启时以「通知进化」为准**：检测到通知进化已启用，自定义通知就不再接管（避免两个实现互相打架、导致通知没人处理）。想用本功能，请先关掉「通知进化」。

## 注意

- 「仅提醒 @所有人」只做得到 @所有人 这一级：通知回调里拿不到消息的 msgSource，无法精确判断「是否 @ 了我」，所以开启后等价于「只留 @所有人 提醒」，@我 的普通提醒也会被静默。这是宿主接口的局限，不是开关坏了。
- 静音时段内被静默的是提醒（声音/振动/展示），消息本身照常入库，错过不了。
- 通知内的回复与已读动作走的是微信自己的接口，需要通知栏权限与后台存活；被系统清理后动作会失效。
- 修改后如果没生效，先确认另一个通知功能已关闭，再重启一次微信。
